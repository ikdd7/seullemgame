# 07-structured — 구조화 질문 데이터셋

`data/02-common`, `data/03-regions`, `data/04-jobs` 아래 마크다운 파일에 수집된
공무원 면접 질문을 AI 시스템에서 바로 사용할 수 있도록 구조화한 JSON 데이터셋.

- **생성 스크립트**: `scripts/build_dataset.py` (Python 표준 라이브러리만 사용)
- **재생성 방법**: 리포지토리 루트에서 `python3 scripts/build_dataset.py`
- **출력 파일**: `data/07-structured/questions.json` (UTF-8, `ensure_ascii=False`)
- 마크다운 원본은 읽기만 하며 수정하지 않는다. 원본이 갱신되면 스크립트를 다시 실행하면 된다.

## 파일 구조

```json
{
  "meta": {
    "name": "korean-civil-service-interview-questions",
    "generated_at": "…",            // 생성 시각 (UTC, ISO-8601)
    "generator": "scripts/build_dataset.py",
    "source_dirs": ["02-common", "03-regions", "04-jobs"],
    "total_questions": 1941,
    "files_scanned": [ {"file": "...", "questions": N}, … ],
    "distributions": { "category": …, "type": …, "reliability": …, "region": …, "job": …, "year": … },
    "schema": { …필드 설명… }
  },
  "questions": [ { …아래 스키마… }, … ]
}
```

## 질문 스키마 (`questions[]`)

| 필드 | 타입 | 설명 |
|---|---|---|
| `id` | string | 고유 ID. `q00001` 형식(파일 정렬 순서 기반 일련번호). 재생성 시 원본 변경에 따라 번호가 밀릴 수 있으므로 영구 키가 필요하면 `text`+`source_file` 해시를 별도로 만들 것 |
| `text` | string | 질문·발표주제 본문. 마크다운 굵게/코드 마커 제거, NFC 정규화, `— 연결 공직가치: …`·`(법률저널 보도)` 류 편집·출처 주석 꼬리 제거 |
| `category` | string | `common`(직렬·지역 공통) / `region`(지역별) / `job`(직렬별) — 원본 디렉토리 기반 |
| `region` | string \| null | 지역명. `03-regions` 파일명 기반(주요시군 파일은 `## 수원시` 등 섹션 제목의 시·군명), 그 외에는 태그(`[2023/서울/정책]` 등)에서 추출. 약칭은 공식 명칭으로 정규화(서울 → 서울특별시) |
| `job` | string \| null | 직렬명. `04-jobs` 파일명 기반(`기타직렬.md`는 섹션 제목의 직렬명), 그 외에는 태그·문두 `(세무직)` 표기에서 추출 |
| `year` | int \| null | 출제(복원) 연도. 태그(`[2021/공통/…]`), 문두 연도, `## 2025년` 류 연도 섹션 제목 순으로 추출. 미상이면 null |
| `type` | string \| null | 질문 유형: `공직가치` `인성` `직무` `지역현안` `상황형` `시사` `발표` `후속` 중 하나. 태그 → 섹션 제목 → 파일명 순으로 추론 |
| `reliability` | string \| null | 신뢰도: `확인`(출처 문서에서 직접 확인) / `복원`(응시자 기억 기반 복원, `복원참고` 포함) / `기출`(기출로 표기) / `예상`(현안 기반 예상·대비 질문) / `빈출`(빈출·단골 표기). 표기가 없으면 null |
| `source_file` | string | 리포지토리 루트 기준 원본 마크다운 경로 |

## 추출 규칙 개요

1. 불릿(`- `, `* `)으로 시작하는 줄만 후보로 본다 (체크박스 `- [ ]`, URL 포함 줄 제외).
2. 다음 중 하나면 질문으로 채택: 물음표 포함 / 명령형 어미(~보라, ~하시오 등)로 종결 /
   `질문1 / 질문2 / …` 형태의 복원 질문 목록 / `[연도/직렬/유형]` 태그 보유(해설성 문장 제외).
3. 출처 안내·면접 형식 설명·복기 메모(예: "게시글 존재, 열람 필요", "평정요소: …", "…라는 후기가 다수")는
   표지어·어미·머리말 사전으로 걸러낸다.
4. 태그를 `/` 로 분해해 연도·지역·직렬·유형·신뢰도를 파싱하고, 태그가 없으면
   섹션 제목·파일명에서 유형/직렬/지역을 보충한다.

## 알려진 한계

- **미분류 필드**: 원본에 태그가 없는 질문(주로 04-jobs 직무 질문)은 `year`(94% 미상)와
  `reliability`(63% 없음)가 null이다. 04-jobs 질문은 특정 연도가 아닌 "직렬 지식 체크리스트" 성격이므로 정상.
- **복합 질문 미분리**: "본인의 장점과 단점은? 그 이유는?"처럼 한 불릿에 2개 이상의 질문이 있는 경우,
  그리고 `자기소개 / 지원동기 / …` 형태의 복원 면접 흐름 목록(약 30건)은 분리하지 않고 한 항목으로 유지했다.
- **발표 제시문 요약**: 국가직 5분발표·상황형 과제의 `확인` 항목 일부는 질문문이 아니라 제시문 시나리오
  요약(예: "무인민원발급기 설치 여부 판단: …")이라 문장이 길고 서술형이다.
- **경계 사례 잔존**: 지역 상식 요약형 항목(예: "충남의 시·군 수(15개: …)")처럼 답이 본문에 포함된
  항목이 소수 남아 있다. 반대로 해설성 필터(어미·표지어 사전)가 태그 있는 요약형 항목
  (예: "…관련 질문", "…빈출")을 제외하므로 진짜 질문 소수가 누락될 수 있다.
- **중복**: 같은 질문이 공통 파일과 지역/직렬 파일에 모두 실린 경우 각각 별개 항목으로 유지된다
  (완전 동일 텍스트는 동일 파일 내에서만 중복 제거). AI 활용 시 임베딩 기반 중복 제거를 권장.
- **id 안정성**: `id`는 실행 시점의 정렬 순서 기반이라 원본 파일 추가·수정 시 재부여된다.
