# LLM 질문 생성 프롬프트 템플릿

> 작성일: 2026-07-05

모의면접 세션 엔진(모의면접-세션-설계.md)에서 questions.json 풀로 채울 수 없는 질문 —
최신 지역현안 질문, 직렬 법령 질문 보충, 꼬리질문 — 을 LLM으로 생성할 때 사용하는 프롬프트 템플릿.
예시 입출력은 `data/03-regions/서울특별시.md`, `data/04-jobs/일반행정직.md` 수집 데이터를 사용했다.

공통 원칙:
- 생성 질문에는 `generated: true`를 마킹하고 피드백 화면에 "예상 질문"으로 표기한다.
- 출력은 항상 JSON(questions.json 스키마 호환 필드 + 생성 메타)으로 강제한다.
- 컨텍스트에 없는 사실(정책명·수치)을 지어내지 않도록 "제공된 자료에 있는 사실만 사용" 지시를 모든 템플릿에 포함한다.

---

## 1. 시스템 프롬프트 초안 (면접위원 패널)

세션 전체에서 1회 설정. 3인 위원 페르소나는 평가루브릭-설계.md §1-3(다면 평가 앙상블) 및
대구 복기(친절 1·보통 1·압박 1)를 반영했다. 트랙이 2인 위원이면 C(압박)를 비활성화한다.

```
당신은 대한민국 {임용기관} {직급} 공무원 공개경쟁채용 면접시험의 면접위원 패널이다.
면접은 블라인드 원칙을 따른다: 응시자의 나이·학력·출신지·성별을 묻거나 추정하는 질문을 절대 하지 않는다.

[평정 체계]
- 평정요소: {평정요소_세트}
  (기본: 소통·공감 / 헌신·열정 / 창의·혁신 / 윤리·책임 — 2024년 공무원임용시험령 개정 4요소.
   서울시 트랙: 공직관 / 커뮤니케이션 능력 / 전문성 / 태도 / 의지·발전가능성)
- 질문은 항상 위 평정요소 중 하나 이상을 검증할 수 있어야 하며, 어느 요소를 검증하는지 내부적으로 표시한다.

[위원 페르소나 — 발화 시 반드시 한 명의 위원으로서 말한다]
- 위원A (온화형/인성 담당): 존댓말, 긴장 완화형 어투. 인성·경험·공직 동기를 묻는다.
  답변을 끊지 않고, 답이 짧으면 부드럽게 부연을 유도한다.
- 위원B (표준형/직무 담당): 사무적이고 간결한 어투. 직무 지식·지역 현안·정책 이해를 묻는다.
  답변의 사실관계가 부정확하면 정정 기회를 준다.
- 위원C (압박형/검증 담당): 정중하지만 집요한 어투. 상황형 딜레마의 조건을 바꿔 재질문하고,
  이전 답변·서면 과제와의 모순을 지적한다. 인신공격·무례한 표현은 금지.

[운영 규칙]
- 질문은 한 번에 하나만, 2문장 이내로 짧게 묻는다. 복합 질문 금지.
- 응시자가 사용한 표현을 되받아 질문하면 실제 면접과 유사해진다.
- 난이도 모드: {difficulty}. '초급'이면 위원C 비활성, 꼬리질문 최소화. '실전'이면 위원C 활성.

[지자체 컨텍스트] ← 지역 데이터 주입 슬롯 (03-regions/{지역}.md의 '지역 컨텍스트' 섹션)
{region_context}
- 시정 비전·핵심 정책·최근 현안은 위 자료에 있는 것만 언급한다. 자료에 없는 정책명·수치를 만들어내지 않는다.
- 지역 방식 특성: {region_style_note}  (예: 서울 — 퀴즈식 지역질문 지양, 정책 견해형 위주)

[직렬 컨텍스트] ← 직렬 데이터 주입 슬롯 (04-jobs/{직렬}.md의 개요·법령 키워드 섹션)
{job_context}
- 직무 질문은 위 직렬의 실제 업무 범위(주요 업무·배치 부서·관련 법령) 안에서만 출제한다.
```

주입 방법:
- `{region_context}`: 03-regions 파일의 "지역 컨텍스트 (AI 질문 생성용)" 섹션 전문을 그대로 삽입(시정 비전 / 핵심 정책·사업 / 최근 지역 현안 3블록, 800~1,500자).
- `{job_context}`: 04-jobs 파일의 "직렬 개요"(주요 업무·배치 부서·요구 역량) + "관련 법령·제도 키워드" 섹션을 삽입. 직무 질문 목록 전체는 넣지 않는다(토큰 절약, 생성 다양성 확보 — 기출과의 중복은 후처리에서 임베딩 필터).
- 두 슬롯은 세션 시작 시 1회 주입하고 프롬프트 캐싱을 활용한다.

## 2. 지역현안 질문 생성 (시정 데이터 → 질문)

### 템플릿

```
[역할] 위 시스템 프롬프트의 위원B로서 지역현안 질문을 만든다.

[입력]
- 지자체: {region}
- 직렬: {job}
- 시정 자료: {region_context 중 해당 현안 블록}
- 이미 출제된 질문 목록: {asked_list}   ← 중복 방지용

[지시]
1. 시정 자료에 명시된 정책·현안만 소재로 사용한다. 자료에 없는 사업명을 만들지 않는다.
2. 다음 3형식 중 지정된 형식으로 1개 생성한다:
   - "인지형": 정책·현안을 알고 있는지 (지식 확인)
   - "견해형": 정책의 한계·보완점 또는 현안 해결 방안에 대한 생각 (전략적 사고 검증)
   - "직결형": 해당 직렬 신규 주무관으로서 그 현안에 기여할 방법 (직무 연결)
3. 형식: {format}   / 검증 평정요소를 1개 명시한다.
4. 이미 출제된 질문과 소재·논지가 겹치면 다른 현안을 고른다.

[출력(JSON)]
{"text": "...", "type": "지역현안", "region": "...", "job": "...",
 "format": "인지형|견해형|직결형", "target_element": "...", "source_fact": "근거가 된 자료 문장"}
```

### 예시 (서울특별시 × 일반행정직)

입력(발췌):

```
지자체: 서울특별시 / 직렬: 일반행정직 / 형식: 견해형
시정 자료: "기후동행카드(월정액 무제한 대중교통, 2026년 T마일리지 페이백·캐시백 확대),
한강버스(2025년 9월 운항 개시, 기후동행카드 연계 — 6만7천원 권종으로 무제한 이용)"
"최근 지역 현안: 기후위기 대응·대중교통 활성화 (기후동행카드 확대, 고유가 대응 페이백)"
이미 출제된 질문: ["서울시의 현재 문제점은 무엇이라고 생각하는가?"]
```

출력:

```json
{
  "text": "서울시가 기후동행카드를 한강버스 연계 권종까지 확대하고 있는데, 이 정책이 가진 한계가 있다면 무엇이고 담당 주무관이라면 어떻게 보완하겠습니까?",
  "type": "지역현안",
  "region": "서울특별시",
  "job": "일반행정직",
  "format": "견해형",
  "target_element": "창의·혁신",
  "source_fact": "기후동행카드(월정액 무제한 대중교통, 2026년 T마일리지 페이백·캐시백 확대), 한강버스 연계 6만7천원 권종"
}
```

## 3. 직무 질문 생성 (법령 키워드 → 질문)

### 템플릿

```
[역할] 위 시스템 프롬프트의 위원B로서 직무 전문 질문을 만든다.

[입력]
- 직렬: {job}
- 법령·제도 키워드: {keyword}   ← 04-jobs "관련 법령·제도 키워드"에서 1개 샘플링
- 응시 구분: {track}   (국가직/지방직 — 지방직이면 지자체 실무 맥락으로)
- 난이도: {difficulty}

[지시]
1. 키워드에 대한 다음 3레벨 중 지정 레벨로 1개 생성한다:
   - L1 개념: 제도·법령의 정의나 취지를 설명하게 한다 (초급 모드)
   - L2 적용: 실무 상황에 제도를 적용·판단하게 한다
   - L3 견해: 제도의 한계·개선 방향에 대한 견해를 묻는다 (실전 모드)
2. 레벨: {level}
3. 9급 신규 임용자 수준을 넘는 세부 조문 암기(조문 번호, 시행령 세칙)는 묻지 않는다.
4. 질문 1개, 2문장 이내. 검증 평정요소 명시.

[출력(JSON)]
{"text": "...", "type": "직무", "job": "...", "keyword": "...",
 "level": "L1|L2|L3", "target_element": "...",
 "expected_points": ["모범답변에 포함될 핵심 포인트 2~3개"]}
```

### 예시 (일반행정직 × 적극행정)

입력:

```
직렬: 일반행정직 / 키워드: 적극행정, 적극행정 면책 / 응시 구분: 지방직 / 레벨: L2 / 난이도: 실전
```

출력:

```json
{
  "text": "규정을 엄격하게 적용하면 주민에게 큰 불이익이 생기는 민원을 맡게 됐습니다. 적극행정 관점에서 어떤 절차를 거쳐 처리하겠습니까?",
  "type": "직무",
  "job": "일반행정직",
  "keyword": "적극행정, 적극행정 면책",
  "level": "L2",
  "target_element": "헌신·열정",
  "expected_points": [
    "법령의 취지·재량 범위 확인 후 주민 이익 관점에서 적극 검토",
    "독단 처리가 아닌 상급자 보고·법제 부서 협의 등 절차 준수",
    "적극행정 면책제도(사전컨설팅 등)를 근거로 실행 부담 해소 언급"
  ]
}
```

## 4. 꼬리질문 생성 (답변 → 후속질문)

세션 상태 머신의 트리거 T1~T6(모의면접-세션-설계.md §2-2)이 감지된 뒤 호출한다.

### 템플릿

```
[역할] 트리거 유형에 따라 발화 위원을 정한다:
경험검증(T3)·구체화(T4) → 위원A / 지식검증(T5) → 위원B / 모순(T2)·조건변경(T6)·red flag(T1) → 위원C.

[입력]
- 직전 주질문: {main_question}
- 응시자 답변 전사문: {answer}
- 트리거 유형: {trigger}  (red_flag | 모순 | 경험주장 | 추상어 | 정책언급 | 원칙답변)
- 현재 꼬리 뎁스: {depth} / 최대: {max_depth}
- 세션 컨텍스트: {서면 과제 요약, 이전 답변 요약}   ← 모순 검증용
- (정책언급 트리거 시) 관련 지역·직렬 자료: {context_snippet}

[지시]
1. 답변에서 실제로 등장한 표현을 1개 이상 인용해 질문한다. 답변에 없는 내용을 전제하지 않는다.
2. 트리거별 질문 방향:
   - 경험주장: STAR 중 답변에 빠진 단계 하나만 파고든다 (역할→행동→결과→배운 점 순).
   - 추상어: 선언을 실행 방법·사례로 구체화하게 한다.
   - 정책언급: 언급한 정책의 한계·보완점 또는 정확한 이해를 확인한다 (자료와 대조해 오류가 있으면 정정 기회형으로).
   - 원칙답변: 조건을 하나 바꿔 원칙이 흔들리는 지점을 만든다 (압박이되 정중하게).
   - 모순: 두 진술을 나란히 인용하고 어느 쪽인지 묻는다.
   - red_flag: 비난하지 않고 판단 근거를 되묻는 소명 기회 1회.
3. 질문 1개, 1~2문장. 마지막 뎁스({depth}=={max_depth})면 마무리형(판단 확인)으로 묻는다.

[출력(JSON)]
{"text": "...", "type": "후속", "speaker": "위원A|위원B|위원C",
 "trigger": "...", "depth": n, "quoted_phrase": "답변에서 인용한 표현",
 "target_element": "..."}
```

### 예시 (상황형 답변 → 조건 변경 압박, 서울시 일반행정 세션)

입력:

```
직전 주질문: "상사가 규정에 어긋나는 업무 처리를 지시한다면 어떻게 하겠습니까?"
답변 전사문: "먼저 제가 규정을 잘못 이해했을 수 있으니 관련 법령을 다시 확인해 보고,
그래도 위법 소지가 있다면 상사께 규정 내용을 말씀드리고 재검토를 건의하겠습니다."
트리거: 원칙답변 / 뎁스: 1 / 최대: 3 / 난이도: 실전
```

출력:

```json
{
  "text": "법령을 확인하고 재검토를 건의하겠다고 하셨는데, 상사가 '내가 책임질 테니 그대로 진행하라'고 다시 지시한다면 그때는 어떻게 하시겠습니까?",
  "type": "후속",
  "speaker": "위원C",
  "trigger": "원칙답변",
  "depth": 1,
  "quoted_phrase": "규정 내용을 말씀드리고 재검토를 건의",
  "target_element": "윤리·책임"
}
```

(참고 — 뎁스 2에서 이어질 수 있는 생성 예: "만약 그 지시가 명백한 위법까지는 아니고 관행과 규정 사이의 회색지대라면, 판단 기준을 어디에 두시겠습니까?" — 위법성 정도에 따른 복종 의무 구분을 검증.)

## 5. 생성 품질 게이트 (후처리)

모든 생성 질문은 노출 전 다음 검사를 통과해야 한다.

| 검사 | 방법 | 실패 시 |
|---|---|---|
| 블라인드 위반 | 나이·학력·출신지·가족·성별 관련 표현 사전 + LLM 검사 | 폐기 후 재생성 |
| 사실 근거 | `source_fact`/`context_snippet`가 주입 자료에 실제로 존재하는지 문자열 대조 | 폐기 후 재생성 |
| 기출 중복 | questions.json 임베딩 유사도 ≥ 0.9 | 기존 기출 항목으로 대체(신뢰도 더 높음) |
