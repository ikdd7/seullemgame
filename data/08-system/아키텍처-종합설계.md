## 1. 시스템 개요

### 1-1. 제품 비전

**"지자체 × 직렬 특화 AI 모의면접"** — 응시자가 실제로 지원하는 **지역(17개 시·도 + 기초)과 직렬(26종)** 의 면접 방식·평정요소·현안을 그대로 재현하는 개인화 모의면접 서비스.

일반적인 AI 면접 연습 서비스가 "범용 인성·직무 질문 + 표정/음성 점수화"에 머무는 것과 달리, 본 서비스는 다음을 정확히 모사한다.

- 실제 공무원 면접 **제도**: 국가직 9급형(경험·상황 과제 작성 → 5분 발표 → 심층면접), 지방직 표준형(사전조사서 → 개별면접), 그리고 서울·부산·대구·인천·경기 등 **지자체별 변형 방식**.
- 실제 **평정 규칙**: 점수 합산이 아니라 위원 과반수의 상/중/하 조합으로 우수/보통/미흡을 판정하는 임계 판정형(공무원임용시험령 4대 평정요소).
- 실제 **꼬리질문 압박**: 경험 주장 STAR 검증, 진술 모순 대질, 상황형 조건 변경 압박 등 위원 페르소나 기반 후속 질의.

### 1-2. 핵심 차별점

| # | 차별점 | 근거 자료 |
|---|---|---|
| 1 | **지자체별 면접 방식 재현** (서울 5분 스피치 / 부산 온화 3분 / 대구 3인 압박 / 인천 모의토론) | 세션 설계 §1-3 |
| 2 | **제도 정합 채점** — 상/중/하 × 위원 과반수 규칙을 그대로 구현(합산 점수 아님) | 루브릭 §1-2 |
| 3 | **위원 페르소나 앙상블** — 온화(A)/표준(B)/압박(C) 다면 평가로 제도 정합성 + LLM 편차 완화 동시 달성 | 루브릭 §1-3, 프롬프트 §1 |

| 6 | **공정성·규제 설계 내장** — 비언어는 등급 미반영(코칭 전용), 블라인드 원칙, AI 생성 표시 | 루브릭 §3-3, 컴플라이언스 §1-2·§2 |

### 1-3. 사용자 여정

```
[회원가입/로그인]
   └ 만 14세 이상 확인 · AI 생성물 고지 동의 · 음성(영상) 수집 동의 · 국외이전 고지
        ↓
[지역/직렬/트랙/난이도 선택]  (INTAKE)
   └ 예) 서울특별시 · 일반행정직 · 서울 스피치 트랙 · 실전 모드 → region_profile 매핑
        ↓
[모의면접 진행]  (PREWORK → SPEECH → INTERVIEW → WRAPUP)
   └ 과제 작성 → 발표/스피치 → 개별면접(주질문+꼬리질문 루프) → 마무리 발언
        ↓
[채점]  (SCORING, 비동기)
   └ 스피치 지표 산출 + 위원 앙상블 채점 + 과반수 집계 + red flag 반영
        ↓
[피드백 리포트]  (FEEDBACK)
   └ 등급 + 요소별 근거 인용 + 스피치 코칭 + 예상 꼬리질문 + 다음 세션 약점 보정 추천
        ↓
[재도전 루프]  약점 유형 오버샘플링 → 다음 세션
```

### 2-3. 핵심 아키텍처 결정 (기술 스택 §6-2)

1. **캐스케이드(STT→LLM→TTS) 채택** — 채점의 원천은 정확한 한국어 전사문이며, 한국어 STT 정확도는 국산 특화 엔진이 우위. S2S(Realtime)는 전사 품질 통제와 국산 STT 결합이 어려워 배제.
2. **지연 예산** — 발화 종료 후 ~1초 내 면접관 첫 음성. 면접 도메인은 1~2초 "생각하는" 지연이 오히려 자연스러워 일반 콜봇보다 여유.
3. **프롬프트 캐싱 극대화** — 면접관 system(페르소나+트랙규칙+지역/직렬 컨텍스트+과제)은 세션 내 완전 동결하여 매 턴 캐시 히트. 채점은 루브릭 전문을 프리픽스로 두고 위원 페르소나만 뒤에 배치.
4. **append-only session_log** — 모든 상태 전환·전사문·질문ID 기록. T2(진술 모순) 대조와 채점 근거 인용의 원천 데이터.

### 3-1. 스토리지 개요

|---|---|---|---|

| **Redis** | 활성 세션 상태·타이머·꼬리 뎁스 스냅샷 | 휘발성, 장애복구 | 저지연 상태 관리 |
| **PostgreSQL** | 사용자, session_log, 피드백 리포트, 동의 이력 | 영구, append-only 로그 | 감사·재현·약점 보정 |
| **Object Storage** | TTS 사전생성 오디오, (동의 시) 음성 원본 | 대용량 | 음성은 저장 최소화·즉시삭제 옵션 |

### 3-2. 질문 뱅크 (questions.json)

데이터셋 리포트가 드러낸 **실제 데이터 특성을 전제로 설계**한다(공백을 숨기지 않는다).

- **규모/분포**: 총 3,122건. 직무 38.5% + 지역현안 30.0%가 무게중심. 반면 공직가치(4.8%)·인성(4.1%)·발표(1.3%)·후속(0.4%)은 희소.
- **핵심 공백 — 지역×직렬 교차 3.4%**: 두 필드 동시 태깅은 106건뿐. → 설계 원칙: **"지역 현안(지역 축) + 직무 질문(직렬 축)을 각각 뽑아 조합"** 한다. 단일 교차 매칭에 의존하지 않는다(리포트 §5-3).
- **신뢰도 라벨**: 고신뢰(확인·복원·기출) 14.6% vs 예상(생성·추정) 19.0%, 미태깅 52.8%.
  - **실전 노출용**은 `reliability ∈ {확인, 복원, 기출}` 우선, `예상`은 워밍업/초급 모드로 분리.
  - 가중치 `w_reliability`(확인 1.0 → null 0.4)로 반영(세션 설계 §3-2).
- **얇은 유형 오버샘플링**: 공직가치·인성·상황형은 의도적 오버샘플링 + 부족분 LLM 생성 보충(`generated: true` 마킹, 피드백에 "예상 질문" 표기).
- **region 라벨 오염**: `중소시군-3차`, `군단위-호남` 같은 배치 라벨이 region 값에 유입됨. → 표준 행정구역명 정규화 매핑 테이블을 별도 유지, 필터는 정규화 값 기준.

질문 레코드(스키마 호환 필드): `id, text, type, category, region, job, reliability, year, target_element, generated`.

### 3-3. 지역/직렬 컨텍스트 (마크다운 → 구조화)

프롬프트 캐싱과 사실 근거 검사를 위해 마크다운을 구조화 레코드로 승격한다.

- **region_profile**: `03-regions/{지역}.md`의 "지역 컨텍스트(AI 질문 생성용)" 섹션(시정 비전 / 핵심 정책·사업 / 최근 지역 현안, 800~1,500자) + 면접 방식 변형(스피치 시간·위원 수·압박 강도·쿼터 조정) + `verified_year`.
- **job_context**: `04-jobs/{직렬}.md`의 직렬 개요(주요 업무·배치 부서·요구 역량) + 관련 법령·제도 키워드. 직무 질문 목록 전체는 넣지 않음(토큰 절약·생성 다양성, 중복은 임베딩 후처리).
- **시효 관리**: `수집일` 헤더가 12개월 초과 시 지역현안 생성에 "최신 여부 확인 필요" 라벨 자동 부착(프롬프트 §5).

### 3-4. 사용자 세션 로그 (session_log)

append-only. 필드: `session_id, ts, state, question_id, speaker, transcript, speech_metrics, trigger, depth`. 용도: (1) T2 진술 모순 대조, (2) 채점 근거 인용의 원천, (3) 약점 보정 샘플링 이력, (4) 자동화 처리 설명 요구(개인정보보호법 제37조의2) 대응 근거.

## 4. 핵심 플로우 3종 (상세)

### 4-1. 질문 출제 플로우

세션 시작 시 개별면접 질문 큐를 구성한다(세션 설계 §3).

```
사용자 선택(region, job, track, difficulty, n=10)
   │
   ▼
[1] 후보 필터링 (완화 단계 — 좁은 조건부터)
      1순위: region==선택 AND job==선택
      2순위: (region==선택 AND job==null) + (job==선택 AND region==null)   ← 축 분리 조합
      3순위: category==common
      (국가직 트랙이면 region!=null 전량 제외)
   │
   ▼
[2] 중복 제거: 임베딩 유사도 ≥0.9 쌍은 reliability 높은 쪽만 유지
   │
   ▼
[3] 유형 쿼터 샘플링 (트랙/지역별 조정)
      지방직 표준: 공직가치2+인성2+직무3+지역현안2+상황형1
      국가직 9급: 공직가치2+인성2+직무3+지역현안0+상황형3
      서울: 인성 강화·시정상식 1문까지 / 대구·경북: 지역현안+1
   │
   ▼
[4] 쿼터 내 가중 선택  w = w_reliability × w_year × w_novelty
      (novelty: 최근 3세션 출제분 0.1로 재출제 억제)
   │
   ├─ 쿼터 미충족 유형 → 필터 한 단계 완화 재시도
   │      └ 그래도 부족 → LLM 생성 (질문생성 템플릿 §2·§3)
   │            └ 품질 게이트(§5): 블라인드·사실근거·기출중복·복합질문·난이도·어투 통과
   ▼
[5] 출제 순서 골격 배치
      (자기소개1)→(공직가치1)→(직무1~2)→(지역현안1)→(상황형1)
      →(직무1~2)→(공직가치1)→(인성1)→(지역현안1)→WRAPUP
      규칙: 동일유형 3연속 금지 · 상황형은 중반 이후 · 발표 제시문은 별도 풀에서 1건
```

발표/스피치 제시문은 `type ∈ {발표}` 풀에서 별도 1건 샘플링(서울 트랙은 인성/시정/시사 균등 확률로 예측 곤란성 재현).

### 4-2. 실시간 면접 대화 플로우 (INTERVIEW 루프)

```
오케스트레이터        STT(리턴제로)      VAD(Silero)     Haiku 판정     Sonnet 생성      TTS            프론트
    │                    │                 │              │              │              │              │
    │ ASK(main_q)────────────────────────────────────────────────────────────────────────────────────▶│
    │ (주질문: 사전생성 오디오 캐시 재생)                                                    ◀재생───────│
    │                    │                 │              │              │              │              │
    │◀────── 사용자 발화 오디오 스트림 ────────────────────────────────────────────────────────────────│
    │  파셜 전사 ◀───────│                 │              │              │              │              │
    │  침묵/무음 감지 ◀────────────────────│              │              │              │              │
    │  ├ 10초 무응답 → "천천히 답하셔도" 프롬프트                                                         │
    │  ├ 30초 무응답 → skip(미흡 신호 기록)                                                              │
    │  └ 3초 무음+종결어 → 발화 종료 확정                                                                 │
    │                    │                 │              │              │              │              │
    │ analyze(answer): 트리거 판정 1회 ──────────────────▶│              │              │              │
    │                              T1~T7 우선순위 판정 ◀──│              │              │              │
    │                                                                                                    │
    │  trigger 有 & depth<max_depth:                                                                     │
    │    후속 매칭(questions.json type=후속) or ─────────────────────────▶│  꼬리질문 스트리밍 생성      │
    │    (꼬리질문 텍스트 첫 청크) ◀──────────────────────────────────────│──────────────▶│ 합성        │
    │    발화 위원 배정(경험T3·구체T4→A / 지식T5→B / 모순T2·조건T6·red T1→C)  ◀ 스트리밍 재생 ──────────▶│
    │    → LISTEN 재진입 (depth+1)                                                                        │
    │                                                                                                    │
    │  trigger 無 or depth==max_depth → NEXT_QUESTION (뎁스 리셋)                                         │
    │  ※ 잔여시간 기반 max_depth 동적 하향(꼬리질문 총 예산 ≤ 면접시간 40%)                                │
    │  ※ 모든 턴 → session_log append (ts·질문ID·전사문·스피치지표·trigger·depth)                         │
```

지연 중첩(STT 파셜 → 트리거 판정 → Sonnet 첫 토큰 → TTS 첫 청크)으로 발화 종료 후 ~1초 내 첫 음성 목표. 주질문은 사전생성 캐시라 지연 0.

### 4-3. 채점·피드백 생성 플로우 (SCORING → FEEDBACK)

WRAPUP 종료 후 비동기 워커에서 실행(루브릭 §4-3, 세션 설계 §5).

```
[SCORING 진입: session_log 전체 로드]
   │
   ▼
① 스피치 지표 확정  [규칙 기반]
     말속도 CPM(350~400 적정, ±80 이탈 코칭) · 필러워드 분당 빈도(답변당 ≤3 목표)
     침묵(첫 발화 지연·2초+ 휴지 빈도) · 답변 길이(30초~1분) · 무응답 카운트
   │
   ▼
② LLM 채점 × 위원 페르소나 N (트랙 위원 수와 일치)  [Opus 4.8, Batch API]
     입력: 루브릭 전문(프리픽스 캐싱) + few-shot 상/중/하 앵커 + 질문·답변·서면과제·이전답변 요약
     출력(JSON): 요소별{판정 상/중/하, 근거, 인용[답변 원문]}, red_flags[], 잘한점, 개선점, 모범방향
     원칙: 근거 나열→판정 순서(후광효과 완화), 인용으로 환각 채점 방지
   │
   ▼
③ 과반수 집계 → 공식 규칙 적용
     전요소 상(과반) → 우수  /  동일요소 하(과반) 또는 2요소 하(과반) → 미흡  /  그 외 보통
     (국가직 2인=만장일치, 대구 3인=2/3)
   │
   ▼
④ red flag 강제 반영 (부정 공직관·위법 정당화·진술 모순·무응답·집단 비하 → 해당 요소 강제 '하')
     ※ 미흡은 실제로 드묾 → red flag 없으면 보수적으로, 대신 "미흡 위험 신호"로 순화(초급 모드)
   │
   ▼
⑤ [FEEDBACK] 리포트 조립
     등급 + 요소별 근거 인용 + 스피치 코칭(비언어는 등급 미반영, 코칭 채널 분리)
     + 예상 꼬리질문 + 약점 보정 다음 세션 추천(하 판정 요소 유형 +1 오버샘플링)
```

**비언어(표정/시선)** 는 채점에 반영하지 않고 코칭 피드백 전용으로 분리한다(공정성 논란·규제 회피, 루브릭 §3-3 / 컴플라이언스 §5).

## 6. 비용 모델

### 6-1. 세션당 예상 비용 (30분 음성 세션, v1 기준)

기술 스택 §6-2의 자릿수 감각을 컴포넌트별로 분해. **가격 변동성이 크므로 구현 후 실측 필요**한 개산이다.

| 컴포넌트 | 산정 근거 | 세션당(원) |
|---|---|---|
| STT (리턴제로) | 시간당 1,000원 × 0.5시간(순발화) | ~500 |
| 면접관 LLM (Sonnet, 스트리밍) | 멀티턴, system 캐싱으로 입력 ~1/10 | 200~400 |
| 트리거 판정 (Haiku, 턴당 1회) | 경량·저지연 | 50~150 |
| 채점 앙상블 (Opus 2~3인, Batch) | 루브릭 프리픽스 캐싱 + Batch 50% 할인 | 200~500 |
| TTS | 주질문 캐시(≈0) + 꼬리질문만 스트리밍 | 50~200 |
| 인프라(오케스트레이터·DB·대역폭) | 상시 비용 배분 | 100~250 |
| **합계** | | **약 1,100~2,000** |

- **텍스트 MVP는 STT/TTS/VAD 비용이 없어 세션당 400~1,000원대**로 더 낮다.
- **비용 절감 레버**: (1) 프롬프트 캐싱(멀티턴 입력 ~1/10), (2) 채점 Batch API(50% 할인), (3) 주질문 TTS 사전생성 캐시, (4) 트리거 판정만 경량 모델.

### 6-2. 손익분기 개산

가정: 세션 원가 1,500원, 결제수수료·환불·CS·마케팅 등 변동비 세션당 +500원(총 변동비 2,000원/세션).

| 요금 시나리오 | 세션당 마진 | 고정비 월 1,000만원 회수 필요 유료세션/월 |
|---|---|---|
| 월 구독 19,900원(월 8세션 이용 가정 → 세션단가 ≈2,488원) | ~488 | 약 20,500 세션 (≈2,560 구독자) |
| 회당 이용권 4,900원 | ~2,900 | 약 3,450 세션 |
| 10회권 29,900원(회당 2,990원) | ~990 | 약 10,100 세션 |

- **월 구독은 헤비유저의 세션 원가가 마진을 잠식**(월 8세션 초과 시 역마진 구간). → 구독에 월 세션 상한 또는 초과분 종량 병행 권장.
- **회당/회차권 모델이 원가 구조와 정합적**. 초기에는 회차권 중심 + 저관여 사용자용 무료 체험 1회(텍스트 MVP)로 유입.
- 위 수치는 고정비·이용빈도 가정에 민감한 **개산**이며, 실제 세션 원가 실측과 이용빈도 데이터 확보 후 재산정해야 한다.

## 7. 리스크 및 대응

컴플라이언스 문서(`data/05-datasets/법적-컴플라이언스.md`)와 직접 연계한다. 상세 조문·체크리스트는 해당 문서를 원천으로 삼는다.

### 7-1. 법적 리스크

| 리스크 | 근거 | 대응 |
|---|---|---|
| **AI 기본법 투명성 의무** (생성형 AI 사용 시 적용) | 컴플 §1-2 (제31조, 위반 시 과태료 3천만원) | 약관·화면에 "질문·피드백은 생성형 AI가 생성" 사전 고지 + 결과 화면 AI 생성 표시. 비용 거의 0이므로 즉시 이행 |
| **고영향 AI 해당 여부** (채용 영역 명시) | 컴플 §1-1 | "채용 결정 미수행 연습 서비스" 논거 내부 메모화. B2B(기관 평가) 확장 시 재검토. 애매하면 과기정통부 고영향 AI 확인 신청 |
| **음성·영상 개인정보 동의** | 컴플 §2-1·§2-2 | 수집 시점 인지 UX(녹음 표시), 목적·항목·기간·거부권 고지. 영상은 온디바이스·집계지표만, 본인확인 미사용으로 민감정보 회피 |
| **LLM API 국외 이전** | 컴플 §2-6 (제28조의8, 처분례 존재) | 처리방침에 이전받는 자·국가·항목·목적·기간 공개. 모델사 zero-retention 계약 확인 |
| **저작권 (질문 데이터)** | 컴플 §4 | 공공저작물(공공누리)·자체 제작·후기 사실정보 재작성 중심. 타사 복원 문제집 복제 금지. 데이터셋 출처 대장 유지 |
| **전자상거래·환불** (유료화 시) | 컴플 §5 | 통신판매업 신고, 신원정보 표시, 7일 청약철회·디지털콘텐츠 예외 사전고지, 미제공분 환불 산식 |

### 7-2. 기술 리스크

| 리스크 | 대응 |
|---|---|
| **한국어 STT 오전사 → 채점 오류** | CER 1위 리턴제로 채택, 파셜+최종 확정 로직, 필러 raw 모드. 채점은 전사문 인용 기반이라 오전사가 근거에 노출됨 → 검토 가능 |
| **LLM 채점 편차** | 위원 페르소나 앙상블 + 과반수 집계, few-shot 상/중/하 앵커, 골든셋 회귀 테스트 |
| **지연(레이턴시)** | 스트리밍 중첩, 주질문 TTS 사전 캐시, 면접 도메인의 1~2초 여유 활용 |
| **데이터 공백(교차 3.4%·미태깅 53%)** | 지역/직렬 축 분리 조합 샘플링, `예상` 라벨 분리 노출, 얇은 유형 생성 보충 + 품질 게이트 |
| **세션 장애 복구** | Redis 스냅샷 + append-only session_log로 상태 재구성 |

### 7-3. 사업 리스크

| 리스크 | 대응 |
|---|---|
| **채점 신뢰도 불신** | 인간 평가자 2인+ ICC/상관 자체 측정·공개(구조화 면접 타당도 r=.51 학술 근거 제시). 미흡 판정 보수화로 이탈 방지 |
| **"합격 보장" 과장광고** | 표시광고법 리스크 → 금지. "연습용이며 실제 결과와 무관" 고지 |
| **월 구독 역마진** | 세션 상한/종량 병행, 회차권 중심 요금, 원가 실측 후 재산정 |

| **비언어 분석 규제·편향** | 등급 미반영(코칭 전용) 원칙 고수. HireVue 표정분석 중단·일리노이 AIVIA 선례 반영 |
