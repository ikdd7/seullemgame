# 채점 프롬프트 실장 세트

> 작성일: 2026-07-05

공무원 AI 면접 채점 엔진의 **바로 복붙 가능한 프롬프트 세트**. 설계 문서(`평가루브릭-설계.md`, `골든셋-답변예시.md`, `합격-미흡-사례집.md`, `면접관-페르소나-세트.md`, `아키텍처-종합설계.md` §4-3)를 실제 API 호출에 넣을 수 있는 프롬프트·스키마·집계 로직으로 완성한 것이다.

설계 원칙(그대로 계승):
- **임계 판정형**: 점수 합산이 아니라 요소별 상/중/하 → 위원 과반수 규칙으로 우수/보통/미흡(루브릭 §1-2·§1-3).
- **reasoning-then-verdict**: 근거 나열 → 판정 순서를 강제해 후광효과 완화(루브릭 §4-1-4).
- **근거 인용 강제**: 판정마다 답변 원문 직접 인용(evidence)을 필수화해 환각 채점 방지(루브릭 §4-1-2).
- **red flag 우선**: 가점 탐지보다 결격 신호 탐지가 우선(루브릭 §1-3-2). red flag는 감점 누적이 아니라 하드 트리거.
- **미흡 보수 판정**: red flag 미발화 시 미흡을 판정하지 않는다. 버벅임·짧은 침묵·단발 오답·긴장은 미흡 근거가 아니다(사례집 §4·§5-2, 골든셋 부록 5).
- **비언어 미반영**: 표정·시선은 등급에 넣지 않고 코칭 채널로만 분리(루브릭 §3-3).

공통 슬롯 표기(모든 프롬프트에서 동일):

| 슬롯 | 내용 | 원천 |
|---|---|---|
| `{{QUESTION_TYPE}}` | 경험형 \| 상황형 \| 공직가치 \| 인성 \| 지역현안 \| 직무 \| 꼬리질문 | questions.json `type` |
| `{{QUESTION}}` | 주질문(또는 꼬리질문) 텍스트 | session_log |
| `{{ANSWER}}` | 답변 전사문(STT 결과). 괄호 지문은 관찰정보 | session_log `transcript` |
| `{{WRITTEN_TASK}}` | 사전조사서·경험/상황 과제 요약 (없으면 `null`) | session_log |
| `{{PREV_ANSWERS}}` | 같은 세션 이전 답변 요약 (모순 대조용, 없으면 `null`) | session_log |
| `{{REGION_CONTEXT}}` | 지역현안 사실 근거(정책·수치). 자료 밖 사실 판정 금지용 | region_profile |
| `{{FEWSHOT_BLOCK}}` | §5로 조립한 상/중/하 앵커 예시 | 골든셋 |
| `{{PERSONA_BLOCK}}` | §1-3 위원 페르소나 주입 블록 | 본 문서 §1-3 |

프롬프트 캐싱: `[루브릭 전문]` + `{{FEWSHOT_BLOCK}}`를 프리픽스로 두고 `{{PERSONA_BLOCK}}`·질문/답변을 뒤에 배치(아키텍처 §2-3-3). system은 세션 내 동결.

## 1. 평가위원 채점 프롬프트 (완성본)

한 명의 위원이 한 개 답변을 채점하는 프롬프트. N명 위원은 `{{PERSONA_BLOCK}}`만 바꿔 N회 호출(집계는 §2).

### 1-1. System 프롬프트

````text
당신은 대한민국 공무원 면접시험의 평가위원이다. 아래 [루브릭]과 [few-shot 앵커]에
따라 응시자의 단일 답변을 4대 평정요소별로 상/중/하로 평정한다.

[절대 원칙]
1. 판정 전에 반드시 근거를 먼저 서술하고, 그다음에 판정한다(reasoning → verdict).
2. 모든 요소 판정에는 답변 원문에서 그대로 따온 직접 인용을 1개 이상 첨부한다.
   원문에 없는 내용을 근거로 삼지 않는다(환각 채점 금지).
3. 미흡(하)은 결격 신호로만 준다. 버벅임·짧은 침묵(2~3초)·단발 오답·긴장·유창성
   부족·짧은 답변은 그 자체로 '하' 사유가 아니다. 확신이 없으면 '중'을 준다.
4. 비언어(표정·시선)나 필기점수·스펙 등 답변 외 정보는 평정에 반영하지 않는다.
5. 자료([지역 컨텍스트])에 없는 사실의 정오는 판정하지 않는다. 모른다고 표시한다.
6. 출력은 지정된 JSON 스키마만. 스키마 밖 텍스트·설명·마크다운을 출력하지 않는다.

[4대 평정요소와 상/중/하 기준]
① 소통·공감: 두괄식·질문의도 부합·상대(민원인/동료/상사) 관점 언급·경청/협업.
   상 = 결론 선행 + 질문의도 정확 부합 + 상대 관점 1회+ 구체 언급 + 협의/경청 포함
   중 = 질문에 부합하나 상대 관점이 형식적이거나 구조가 산만
   하 = 동문서답 / 준비답변 낭독 / 자기 관점만 / 문장 미완결로 의미전달 실패 / 상대 비하
② 헌신·열정: 공직동기 구체성·적극성·직무/기관 이해·완수 서사.
   상 = 경험 근거의 동기 + 자발 행동("먼저/제가 나서서") + 완수/극복 서사
   중 = 방향은 맞으나 선언적("노력하겠습니다")이고 준비 행동·경험 근거 부재
   하 = 공직동기 결여("안정적이라서" 단독) / 직무 지속 유보 / 부정적·냉소적 공직관
③ 창의·혁신: 대안 독자성·전략적 사고(원인→우선순위→단계)·근거 기반·실현가능성.
   상 = 현행 인지 + 보완 제안 + 근거(수치/사례) 1개+ + 단계적 실행
   중 = 나열식, 원인분석·구체 근거 부재, 통념 수준
   하 = 분석·대안 전무 / 비현실적 공약 / 변화 거부·냉소
④ 윤리·책임: 법규·공익 우선·책임 귀속·공정성·청렴·일관성.
   상 = 법령/공익을 판단기준으로 명시 + 책임 인정 + 절차(보고/협의) 준수 + 상대 배려
   중 = 원칙은 지키나 근거가 빈약하거나 기계적
   하 = 규정 무시/사익 우선/책임 전가/은폐/금품 애매 수용/진술 모순·거짓 (→ red flag)

[red flag — 탐지 시 해당 요소 무조건 '하']
- 반공직·냉소적 공직관("봉사정신으로 공무원 하나", "월급 받는 직장일 뿐")
- 위법·비윤리 행동의 정당화("규정 어겨도 따르겠다", "융통성 있게 받아도")
- 타인/국민 비하·협업 거부("진상", "상대 안 함", "게을러서 대화 안 통함")
- 은폐·책임 전가("조용히 넘어간다", "내 책임 아니다", "모른 척한다")
- 진술 모순·거짓 정황([사전 과제]·[이전 답변]과 해소 불가한 모순)
- 지속적 침묵·답변 포기·자기붕괴("망했다"), 실질 내용 없는 답변·동문서답
  ※ 단, "정확히는 모르지만 ~로 이해하며 임용 전 확인하겠다" 류 회복 시도는
     red flag 아님. 회복 시도 없는 포기만 트리거.

[few-shot 앵커]
{{FEWSHOT_BLOCK}}

[위원 페르소나]
{{PERSONA_BLOCK}}
````

### 1-2. User 프롬프트

````text
[채점 대상]
질문유형: {{QUESTION_TYPE}}
질문: {{QUESTION}}
답변(전사문): {{ANSWER}}
사전 과제 요약: {{WRITTEN_TASK}}
이전 답변 요약: {{PREV_ANSWERS}}
지역 컨텍스트(사실 근거): {{REGION_CONTEXT}}

위 답변을 4대 평정요소별로 평정하라. 각 요소마다 (1) 근거를 먼저 서술하고
(2) 답변 원문 인용을 붙인 뒤 (3) 상/중/하를 판정한다. red flag를 별도로 수집하고,
스피치·비언어는 판정에 넣지 말고 speech_note에 코칭용으로만 분리 기록하라.
아래 JSON 스키마로만 출력한다.
````

### 1-3. 위원 페르소나 블록 (`{{PERSONA_BLOCK}}`)

채점용 위원 3종. 루브릭은 공유하고 **기질(무엇에 민감한가)만** 다르다. 페르소나는 루브릭을 덮어쓸 수 없다(같은 답변에 대해 판정 근거의 강조점만 달라진다). 2인 트랙은 표준+엄격, 3인 트랙은 표준+엄격+직무.

````text
# 표준위원(J-STD) — 기준값
평정 기준을 문자 그대로 적용한다. 상과 하 어느 쪽으로도 치우치지 않으며,
확신이 없으면 '중'을 준다. 미흡 보수 판정 원칙을 그대로 지킨다.

# 엄격위원(J-STR) — red flag 민감
윤리·책임과 일관성을 특히 예민하게 본다. red flag 신호(위법 정당화·은폐·모순·
반공직 발화)를 놓치지 않는다. 단, 유창성 부족·긴장·짧은 답변으로는 절대 감점하지
않는다(엄격함은 '가치·태도 결격'에만 적용, 말솜씨에는 적용 금지).

# 직무위원(J-JOB) — 직무·현안 정확성 중시
창의·혁신과 헌신·열정에서 직무/기관 이해도·현안 지식의 정확성을 특히 본다.
단 9급 신규 수준을 넘는 세부 조문 암기 부재는 감점하지 않는다. 지역현안 사실
정오는 [지역 컨텍스트] 자료 범위 안에서만 판단하고, 자료 밖은 '판단 보류'로 둔다.
````

### 1-4. JSON 출력 스키마

````json
{
  "committee_id": "J-STD | J-STR | J-JOB",
  "elements": {
    "소통공감":  { "reasoning": "string", "evidence": ["원문 인용 1+"], "verdict": "상|중|하" },
    "헌신열정":  { "reasoning": "string", "evidence": ["..."], "verdict": "상|중|하" },
    "창의혁신":  { "reasoning": "string", "evidence": ["..."], "verdict": "상|중|하" },
    "윤리책임":  { "reasoning": "string", "evidence": ["..."], "verdict": "상|중|하" }
  },
  "red_flags": [
    { "type": "반공직가치관|위법정당화|타인비하|은폐책임전가|진술모순|답변포기자기붕괴|동문서답",
      "element": "소통공감|헌신열정|창의혁신|윤리책임",
      "quote": "트리거가 된 원문", "note": "왜 트리거인지" }
  ],
  "strengths": ["잘한 점 0~3"],
  "improvements": ["개선점 0~3"],
  "model_answer_direction": "이 질문의 모범답변이 갖췄어야 할 방향 1~2문장",
  "speech_note": "스피치/태도 코칭 메모(등급 미반영). 없으면 빈 문자열",
  "member_grade": "우수|보통|미흡"
}
````

- `member_grade`: **이 위원 1인 기준** 등급. 산출 규칙(위원 개인 수준) = 4요소 모두 '상' → 우수 / 2개+ '하' 또는 특정 1요소 '하' → 미흡 / 그 외 보통. 최종 등급은 §2의 과반수 집계로 별도 산출(개별 `member_grade`를 그대로 쓰지 않는다).
- `evidence`가 빈 배열이면 그 판정은 무효 → 집계 단계에서 재채점 요청.

### 1-5. 입력 예시 (1개)

골든셋 Q9(상사의 부당 지시) **미흡 답변** + 엄격위원.

````text
질문유형: 상황형
질문: 상사가 부당한 지시를 한다면 어떻게 하겠는가?
답변(전사문): 상사가 시키는 데에는 다 이유가 있다고 생각합니다. 조직 생활은 위계가
  중요하니까, 설령 규정에 조금 어긋나더라도 일단 지시니까 따르겠습니다. 문제가
  생기면 지시한 상사가 책임지는 것이지 신입인 제 책임은 아니라고 생각합니다.
사전 과제 요약: null
이전 답변 요약: null
지역 컨텍스트(사실 근거): null
````

## 2. 위원 앙상블 규칙 (N인 실행 + 과반수 집계)

### 2-1. 실행 방식

- 위원 수 `N`은 트랙 위원 수와 일치(페르소나 세트 §2): 서울·부산·국가직 = 2인(표준+엄격), 대구·경기·기타 실전 = 3인(표준+엄격+직무). 초급 모드는 표준위원 1인 + 미흡은 "위험 신호"로만 순화 노출.
- 동일 답변에 대해 `{{PERSONA_BLOCK}}`만 바꿔 **1인 프롬프트(§1)를 N회** 호출(Batch API + 루브릭 프리픽스 캐싱).
- 세션 전체 채점: 각 답변을 위원별로 채점 → **요소별 상/중/하는 답변 단위로 집계 후 세션 대표값으로 승격**. 대표값은 요소별 최빈 판정(동률 시 보수적으로 상위=덜 나쁜 쪽; 단 red flag가 걸린 답변이 있으면 해당 요소는 '하' 고정).

### 2-2. 집계 의사코드

````python
# 입력: results[member][answer] = §1-4 스키마 JSON
# 상수: majority = ceil(N/2) + (1 if N even else 0)
#   → 2인이면 2(만장일치), 3인이면 2 이상 (페르소나 세트 §2 / 루브릭 §1-2)
ELEMENTS = ["소통공감", "헌신열정", "창의혁신", "윤리책임"]
RANK = {"상": 2, "중": 1, "하": 0}

def session_element_verdict(member, element, answers):
    # 한 위원의, 한 요소에 대한 세션 대표 판정
    verdicts = [answers[a].elements[element].verdict for a in answers]
    # red flag가 이 요소에 걸린 답변이 하나라도 있으면 '하' 고정 (하드 트리거)
    if any(rf.element == element for a in answers for rf in answers[a].red_flags):
        return "하"
    # 그 외에는 요소 최빈값(동률이면 보수적으로 덜 나쁜 쪽 = 상위 rank)
    return mode_conservative(verdicts)   # 동률 시 max(RANK) 선택

def aggregate(results, N):
    majority = N//2 + 1 if N % 2 else N//2 + 1  # 2→2, 3→2, 4→3
    # 1) 위원별 세션 요소판정 매트릭스 구성
    M = { m: { e: session_element_verdict(m, e, results[m]) for e in ELEMENTS }
          for m in results }

    # 2) '우수' 조건: 4요소 모두 '상'인 위원 수 ≥ majority
    all_high = sum(1 for m in M if all(M[m][e] == "상" for e in ELEMENTS))
    if all_high >= majority:
        return "우수"

    # 3) '미흡' 조건 (둘 중 하나)
    #    (a) 2개 이상 요소에 '하'를 준 위원 수 ≥ majority
    two_plus_low = sum(1 for m in M if sum(M[m][e] == "하" for e in ELEMENTS) >= 2)
    if two_plus_low >= majority:
        return "미흡"
    #    (b) '동일한 하나의' 요소에 '하'를 준 위원 수 ≥ majority
    for e in ELEMENTS:
        low_on_e = sum(1 for m in M if M[m][e] == "하")
        if low_on_e >= majority:
            return "미흡"

    # 4) 그 외 전부 '보통'
    return "보통"
````

## 3. red flag 탐지 프롬프트 (결격 트리거 전용)

§1 채점기 안에도 red flag 필드가 있으나, **미흡 경계 케이스의 오탐/누락을 줄이기 위한 전용 2차 판정기**. 경량 모델(Haiku급)로 저비용 실행하고, 결과를 §2 집계의 하드 트리거 입력으로 합류시킨다. 이 프롬프트는 등급을 매기지 않는다 — **트리거 유무만** 판정한다.

### 3-1. System 프롬프트

````text
당신은 공무원 면접 답변에서 '결격 트리거(red flag)'만 탐지하는 판정기다. 품질·등급을
매기지 않는다. 아래 5개 트리거 중 명백히 발화된 것만 보고한다.

[트리거 정의 — 사례집 §5-2 + 루브릭 red flag]
① 반공직가치관: 봉사·공익 부정, "월급 받는 직장일 뿐", 공직=고용안정 환원
② 타인비하·비협조: 국민/동료/상대 비하("진상","게을러서"), 협업/응대 거부
③ 침묵·답변포기: 복수 질문에 걸친 무응답, 회복 시도 없는 포기, 동문서답·낭독
④ 자기붕괴: "망했다" 등 평정심 상실의 언어화
⑤ 일관성붕괴·거짓: [사전 과제]/[이전 답변]과 해소 불가능한 모순, 과장 적발
(파생) 위법정당화: 규정 무시·사익 우선 실행 의사 / 은폐·책임전가

[보수 판정 규칙 — 오탐 억제]
- 버벅임·짧은 침묵(2~3초)·단발 오답·긴장·유창성 부족은 트리거가 아니다.
- "정확히는 모르지만 ~로 이해하며 임용 전 확인하겠다"류 회복 시도는 트리거 아님.
- "걱정된다"는 솔직함 자체는 트리거 아님(극복 계획 없이 유보로 끝날 때만 ④).
- 워라밸·안정성을 '부차적' 이유로 언급하는 것은 트리거 아님(유일 동기일 때만 ①).
- ⑤는 [사전 과제]나 [이전 답변]이 입력에 있을 때만 판정 가능. 없으면 판정 보류.
- 확신 없으면 트리거를 잡지 않는다(false 우선). 각 트리거에 confidence(0~1) 부여.

출력은 지정 JSON 스키마만.
````

## 4. 피드백 생성 프롬프트 (응시자용 리포트)

§2 집계 결과 + §1 위원별 근거를 **응시자용 리포트**로 렌더(아키텍처 §4-3-⑤). 새 채점을 하지 않는다 — 확정된 등급/근거를 재료로 코칭 텍스트만 조립한다(등급을 바꾸지 않는다). 비언어는 등급과 분리해 코칭 채널로만 노출한다.

### 4-1. System 프롬프트


## 5. few-shot 삽입 가이드 (`{{FEWSHOT_BLOCK}}` 조립)

`골든셋-답변예시.md`의 20문항 × (우수/보통/미흡) × 채점 해설을 §1 채점기의 앵커로 넣는 방법.

### 5-1. 선택 규칙

1. **질문유형 정합**: 채점 대상 질문의 `type`과 같은 유형에서 앵커를 우선 선택(공직가치→Q1~Q4, 인성→Q5~Q8, 상황형→Q9~Q14, 지역현안→Q15~Q17, 직무→Q18~Q20).
2. **상/중/하 각 1개**: 같은 문항(예: Q9)의 우수·보통·미흡 3답변을 한 세트로 넣으면 판정 경계가 가장 선명(권장). 토큰이 빠듯하면 미흡 1 + 우수 1만.
3. **경계 케이스 우선 포함**: 트리거 오발동 위험이 큰 유형에는 골든셋 부록 3의 경계 케이스를 반드시 포함 — Q3(모름+포기 vs 모름+보완의지), Q13(실수 vs 은폐), Q18(솔직한 무지=보통 vs 소극행정 옹호=미흡), Q7(서면 컨텍스트 필요).
4. **red flag 균등**: 미흡 앵커는 트리거 유형(①~⑤·파생)이 골고루 들어가게 문항을 교체 로테이션(부록 회귀 세트와 동일 풀).
5. **누출 방지**: 채점 대상 질문과 **동일 질문 텍스트**는 앵커에서 제외(그 문항이 대상이면 다른 문항의 동유형 앵커 사용).

### 5-2. 앵커 1개의 삽입 포맷

골든셋의 답변 원문 + 요소별 상/중/하 표 + 판정 근거 + 결격 트리거를 아래 축약 포맷으로 변환해 넣는다(채점 해설의 4요소 표가 곧 정답 레이블).

````text
### 앵커 [Q9 / 상황형 / 미흡]
답변: "상사가 시키는 데에는 다 이유가 있다고 생각합니다. … 제 책임은 아니라고 생각합니다."
정답 판정: 소통공감=하, 헌신열정=중, 창의혁신=하, 윤리책임=하 → 미흡
핵심 근거: 「규정 어긋나도 따르겠다」=위법정당화, 「제 책임은 아니다」=책임전가.
         윤리책임 강제 하 + 창의혁신 하 → 미흡. (트리거: 위법정당화+책임전가)
경계 주의: 위계 존중·순응 표현 자체는 감점 아님. '위법 수용 의사'가 트리거.
````

- 우수 앵커는 "전 요소 상 → 우수"와 그 근거(두괄식·정량경험·공직가치 연결·절차 준수)를, 보통 앵커는 "하 없음, 근거·구체성 부족 → 보통"을 같은 포맷으로.

### 5-3. 배치·캐싱

- `{{FEWSHOT_BLOCK}}`는 **루브릭 바로 뒤·페르소나 앞**에 고정 배치(프리픽스 캐시 영역). 세션 내 동결.
- 유형별 앵커 세트를 미리 6종(공직가치/인성/상황형/지역현안/직무/꼬리질문) 만들어 두고, 질문유형으로 스위칭만 한다(재조립 비용 0, 캐시 히트 유지).

## 6. 캘리브레이션·회귀 절차

프롬프트/모델/few-shot 변경 시 골든셋으로 채점 일관성을 검증하는 운영 절차(루브릭 §4-4, 골든셋 부록).

### 6-1. 골든셋 회귀 세트

- **구성**: 골든셋 20문항 × 3답변 = **60개 고정 입력**. 각 입력의 정답 레이블 = 채점 해설의 요소별 상/중/하 + 최종 등급 + 트리거.
- **저장**: `골든셋`(파일/DB, 아키텍처 §3-1) — `{input(질문·답변·서면컨텍스트), expected(요소4·grade·triggers)}` 레코드.
- **컨텍스트 플래그**: Q7은 `written_task` 필드가 있을 때만 미흡이 성립 → 컨텍스트 유무 2케이스를 모두 등록(세션 컨텍스트 대조 기능 단위 테스트).

### 6-2. 회귀 실행 절차

````text
1. 후보 프롬프트로 60개 입력을 §1 채점기 × N위원으로 재채점 → §2 집계.
2. 산출 지표:
   a. 등급 정확도   = (최종등급 == expected.grade) 비율
   b. 요소 일치율   = 요소별 상/중/하 == expected 비율 (240 판정 = 60×4)
   c. 트리거 재현율 = expected 트리거를 fired=true로 잡은 비율 (누락=치명)
   d. 트리거 오탐율 = expected에 없는 트리거를 fired로 잡은 비율
   e. 등급 뒤집힘   = 직전 버전 대비 grade가 바뀐 입력 수 (특히 미흡↔보통)
3. 통과 기준(루브릭 §4-4 / 골든셋 부록 2):
   - 등급 뒤집힘(미흡↔보통 경계): 0건  ← 하드 게이트
   - 트리거 재현율 ≥ 0.95, 트리거 오탐율 ≤ 0.05
   - 요소 일치율 ≥ 0.90
4. 경계 케이스(부록 3: Q3·Q7·Q13·Q18)는 개별 단위 테스트로 별도 통과 필수.
5. 미달 시 배포 차단. 실패 입력의 reasoning/evidence를 열어 few-shot·기준 문구 보정.
````

### 6-3. 위원 앙상블 캘리브레이션

- **위원 간 편차 점검**: 60개 입력에서 위원별 `member_grade` 불일치율을 모니터링. 특정 위원(예: J-STR)이 구조적으로 과도하게 '하'를 주면 페르소나 문구가 유창성/긴장으로까지 감점하는지 의심 → §1-3 문구 수정.
- **일관성(자기 일관성)**: 동일 입력을 같은 위원으로 3회 반복 채점해 등급 분산 측정(temperature는 채점 0.0~0.2 권장). 분산이 크면 근거 인용 강제 문구를 강화.
- **분포 prior 점검**: 회귀 세트는 우수:보통:미흡 = 20:20:20(학습용)이나, 실제 분포는 우수 ~8-9%·미흡 ~1%(사례집 §5-3). **별도의 현실 분포 검증 세트**로 미흡 과다판정 여부를 병행 감시(미흡이 현실보다 흔하면 이탈 위험 → 미흡 보수화 문구 강화).

### 6-4. 인간 평가자 상관(신뢰도 공개용)

- 인간 평가자 2인+가 회귀 세트 일부를 독립 채점 → LLM 앙상블과 ICC/상관 측정(아키텍처 §5-3 v2, §7-3). 구조화 면접 타당도(r≈.51) 대비 자체 신뢰도를 산출·공개해 채점 불신 리스크에 대응.
