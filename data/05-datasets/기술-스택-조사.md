## 1. 한국어 STT (음성인식)

### 1-1. 정확도 벤치마크 (리턴제로 공개 벤치마크, AI-Hub 6개 도메인 × 3,000샘플)

한국어는 교착어 특성상 WER보다 **CER(문자 오류율)** 이 적합한 지표다.

| 엔진 | 평균 CER | 비고 |
|---|---|---|
| **리턴제로(RTZR/VITO)** | **5.91%** | 국내 벤치마크 1위. 자체 엔진 + Whisper 계열 엔진 모두 상위권 |
| **네이버 클로바 스피치** | 7.52% | 국내 2위 |
| AWS Transcribe | 8.89% | |
| Azure Batch STT | 9.56% | |
| ETRI | 10.19% | 공공 API(무료 쿼터) |
| OpenAI Whisper (API) | 11.34% | zero-shot 기준 |
| Google Cloud STT v2 | 11.59% | |

- Whisper large-v3의 한국어 zero-shot CER은 약 11.1%(KsponSpeech Eval-Other) 수준으로 영어(3.9%) 대비 크게 떨어짐. 단, **파인튜닝 시 CER 6%대까지 개선** 가능(Whisper-small 18.05%→6.45% 사례). 즉 오픈소스 자체 호스팅은 "파인튜닝 + 운영 부담"을 감수할 때만 유효.

### 1-2. 실시간성·가격 비교

| 옵션 | 실시간 스트리밍 | 가격(대략) | 평가 |
|---|---|---|---|
| **리턴제로 RTZR STT** | ✅ (WebSocket 스트리밍, 저지연) | 무료 10시간 후 **시간당 1,000원**(≈분당 ~17원), 볼륨 할인 | 정확도 1위 + 국내 최저가급. **1순위 후보** |
| 네이버 클로바 스피치 | ✅ (gRPC 스트리밍) | 구간 과금(공식 페이지 요확인. 장문/스트리밍 요금제 별도) | 정확도 2위, 국내 규정·레퍼런스 풍부. 공공기관용 gov-ncloud 존재 → 공무원 도메인에 유리 |
| Google Cloud STT | ✅ | $0.024/분(표준)~$0.036/분 | 한국어 정확도 하위권 |

| AWS Transcribe | ✅ | 배치 $0.024/분, 스트리밍 $0.030/분 | 중간 성능/중간 가격 |
| OpenAI gpt-4o-transcribe / whisper-1 | 제한적(Realtime API 경유) | gpt-4o-transcribe ~$0.006/분, gpt-4o-mini-transcribe ~$0.003/분 | 매우 저렴하나 한국어 CER 열세, 스트리밍 파이프라인 구성 복잡 |
| Whisper 자체 호스팅(faster-whisper 등) | 준실시간(청크 처리) | GPU 인프라 비용만 | 파인튜닝 없인 정확도 부족. 초기에는 비권장 |

### 1-3. 권장

- **주 엔진: 리턴제로 RTZR STT(스트리밍)** — 한국어 정확도 최고 + 저가 + 실시간.
- **대안/이중화: 클로바 스피치** — 공공기관 클라우드 요건(민간 클라우드 제한)이 생길 경우 대비.
- 세션 설계 문서의 "발화 종료 감지(3초 무음 + 종결어)"는 STT 파셜 결과 + 별도 VAD(§2) 조합으로 구현.

## 2. 음성 분석 (말속도 · 필러워드 · 침묵)

### 2-1. 말속도 (CPM/SPM)

- 구현: **STT 전사문 글자 수(공백 제외) ÷ 발화 시간(분)** 으로 CPM 산출. 발화 시간은 VAD로 침묵 구간을 제외한 순발화 시간을 쓰는 방식과 총 응답 시간을 쓰는 방식 두 가지를 병기 권장.
- 기준치: 한국어 발표 도구들은 보통 **330 CPM(느림) ~ 430 CPM(보통) ~ 530 CPM(빠름)** 을 쓰고, TV 뉴스 아나운서 실측은 **약 353~357 SPM(분당 음절)**. 세션 설계 문서의 "350~400 CPM 기준"과 정합 — 350~400을 '적정 구간'으로 두고 ±80 이탈 시 코칭 신호로 처리하면 된다.
- 라이브러리: 전사 기반 계산은 별도 라이브러리 불필요. 음향 기반 검증이 필요하면 `librosa`(에너지·onset), `parselmouth`(Praat 파이썬 바인딩 — 음절 핵 검출로 SPM 추정) 사용 가능.

### 2-2. 필러워드('음', '어', '그') 검출

두 가지 접근을 병행:

1. **전사문 기반(1차, 간단)**: STT가 필러를 전사해 주는 엔진을 선택하고(리턴제로는 옵션 제공, Azure는 기본적으로 필러 제거하므로 raw 옵션 필요), 정규식/토큰 매칭으로 '음', '어', '그', '뭐랄까', '약간' 등을 카운트. 단, 상용 STT는 필러를 지우는 경향이 있어 **재현율이 낮을 수 있음**.
2. **음향 기반(2차, 정밀)**: 
   - **CrisperWhisper** — Whisper 파인튜닝 모델로 verbatim(있는 그대로) 전사 + 단어 단위 타임스탬프 정확도 개선, 필러 이벤트 검출 SOTA. 오픈소스.
   - 학술적으로는 filled pause 검출 전용 분류기(arXiv 2203.15135 "Filler Word Detection and Classification: A Dataset and Benchmark" — PodcastFillers 데이터셋) 접근이 있으나 영어 중심. 한국어는 자체 소량 데이터로 keyword-spotting 파인튜닝 필요.
- MVP 권장: 전사 기반 카운트로 시작 → 코칭 정밀도가 필요해지면 CrisperWhisper류 verbatim 전사 병행.

### 2-3. 침묵 구간 측정 (VAD)

| 라이브러리 | 방식 | 특징 |
|---|---|---|
| **Silero VAD** ✅권장 | DNN(ONNX) | 1.8MB 경량, 30ms 청크를 ~1ms에 처리. 5% FPR에서 TPR 87.7%로 WebRTC(50%) 대비 오류 1/4. 서버·브라우저(onnxruntime-web) 모두 가능 |
| WebRTC VAD | GMM | 매우 빠르나 정확도 낮음(잡음 환경 취약) |
| pyannote-audio | DNN | 최고 정확도급이나 무겁다(화자 분리까지 필요할 때) |
| auditok / pyAudioAnalysis | 에너지 기반 | 의존성 없는 간단 세그먼테이션 |

- 구현: Silero VAD로 스피치/침묵 세그먼트 타임라인 생성 → "질문 후 첫 발화까지 지연(response latency)", "발화 중 2초 이상 침묵 횟수", "총 침묵 비율" 산출. 세션 설계 문서의 "10초 무응답 프롬프트 / 30초 무응답 skip" 트리거도 동일 VAD 스트림으로 구동.

## 3. LLM 선택지 (면접관 대화 · 채점)

### 3-1. 후보 비교

| 모델 | 입력/출력 ($/1M tok) | 프롬프트 캐싱 | 한국어 성능 | 비고 |
|---|---|---|---|---|
| **Claude Opus 4.8** (`claude-opus-4-8`) | $5 / $25 | 읽기 ~0.1×, 쓰기 1.25×(5분 TTL)·2×(1h) | 매우 우수 | 채점(루브릭 판정)처럼 정확성이 중요한 단계에 적합. 1M 컨텍스트 |
| **Claude Sonnet 4.6 / Sonnet 5** | $3 / $15 (Sonnet 5는 2026-08-31까지 $2/$10 프로모션) | 동일 구조 | 매우 우수 | 면접관 대화(꼬리질문 생성) 주력 후보 — 품질/비용 균형 |
| **Claude Haiku 4.5** | $1 / $5 | 동일 구조 | 우수 | 꼬리질문 트리거 판정(T1~T7) 같은 경량 분석 1회 호출용 |
| GPT-4.1 | $2 / $8 (캐시 입력 $0.5) | 캐시 입력 최대 ~75-90% 할인 | 우수 | 1M 컨텍스트. GPT-4o($2.5/$10)의 후속 권장 모델 |
| GPT-4.1 mini | $0.4 / $1.6 | 캐시 $0.10 | 양호 | 경량 판정용 대안 |
| **HyperCLOVA X (HCX-007/005)** | 토큰당 원화 과금, 입력/출력 분리(공식 가격표 요확인) | — | 한국어 특화(KMMLU·HAERAE 우수) | **한국어 토크나이저 효율**이 높아 동일 텍스트 토큰 수가 적음. 공공기관 클라우드(gov-ncloud) 제공 → 공공 조달 요건 시 강점 |

참고: 한국어 벤치마크는 KMMLU(한국 시험 기반 MMLU, 네이버클라우드+EleutherAI+HAERAE 공동)가 표준. HyperCLOVA X 계열은 KMMLU-Pro/HAERAE/KoBALT에서 강세지만, 최상위 글로벌 프론티어 모델(Claude/GPT)의 한국어 추론·지시이행 능력이 전반적으로 앞선다는 평가가 일반적.

### 3-2. 비용 구조 설계 포인트 (프롬프트 캐싱)

면접 세션은 "긴 고정 컨텍스트(루브릭 + 위원 페르소나 + 지역 프로파일 + 작성 과제) + 턴마다 갱신되는 대화"라 **프롬프트 캐싱 효과가 극대화되는 워크로드**다.

- 캐싱은 **프리픽스 매칭**: `tools → system → messages` 순서로 렌더링되며, 앞부분 1바이트만 바뀌어도 이후 전체가 무효화된다. 따라서:
  - system 프롬프트(면접관 페르소나·루브릭·트랙 규칙)는 **세션 내 완전 동결**. 타임스탬프·세션ID 인터폴레이션 금지.
  - 매 턴 붙는 것(새 답변 전사문)은 messages 끝에만 추가, 마지막 턴에 `cache_control` 브레이크포인트.
- Claude 기준: 캐시 읽기 ~0.1× / 쓰기 1.25×(5분 TTL) → 2회 이상 재사용이면 이득. 멀티턴 면접(10~20턴)에서는 입력 비용이 사실상 1/10 수준으로 떨어짐.
- OpenAI는 자동 프리픽스 캐싱(캐시 입력 50~90% 할인, 모델별 상이).
- 채점 앙상블(위원 2~3인 페르소나 × 동일 전사문)은 지연에 둔감하므로 **Batch API(양사 50% 할인)** 로 돌리면 추가 절감.

### 3-3. 권장 조합 (세션 설계 문서 §5와 정합)

| 역할 | 모델 | 근거 |
|---|---|---|
| 면접관 대화·꼬리질문 생성 | Claude Sonnet 급 (또는 GPT-4.1) | 스트리밍 응답 + 한국어 자연스러움 + 페르소나 유지 |

## 5. 표정/시선 분석 (선택 기능)

- **MediaPipe Face Landmarker (Web/JS)** — `@mediapipe/tasks-vision` NPM 패키지. 브라우저에서 WebAssembly+GPU로 동작, 3D 랜드마크 + **블렌드셰이프(표정 계수)** + 변환 행렬 출력. 실시간(라이브 스트림) 지원.
- 시선(gaze)은 Face Landmarker 자체 기능이 아니라 **홍채(iris) 랜드마크**로 근사 추정(MediaPipe Iris/FaceMesh 홍채 포인트 + 머리 자세 행렬 조합). 정밀 시선 추적은 아니며 "화면 응시 이탈 빈도" 수준의 신호로만 활용 가능.
- **개인정보 관점: 온디바이스(브라우저 내) 처리 강력 권장.**
  - 영상 원본·생체 데이터를 서버로 전송하지 않고, 브라우저에서 산출한 **집계 지표(시선 이탈 횟수, 미소 비율 등)만** 서버에 올리는 구조.
  - 얼굴 영상은 생체정보로서 개인정보보호법상 민감정보에 준하는 취급 필요 — 수집 시 별도 동의, 저장 최소화. 미국에서도 AI 채용 표정 분석은 규제 대상(일리노이 AIVIA 등)이며 HireVue도 2021년 표정 분석을 중단한 전례가 있음.
  - 세션 설계 문서 원칙("비언어는 등급 미반영")과 정합: **표정/시선은 채점에 반영하지 않고 코칭 피드백 전용**으로 한정할 것.

## 6. 아키텍처 제안

`모의면접-세션-설계.md`의 상태 머신(INTAKE → PREWORK → SPEECH_PREP → SPEECH → SPEECH_QA → INTERVIEW → WRAPUP → SCORING → FEEDBACK)과 INTERVIEW 내부 루프(ASK → LISTEN → FOLLOWUP↺ → NEXT_QUESTION)를 전제로 한 참조 아키텍처.

### 6-1. 전체 구성

```
[브라우저 (React/Next.js)]
  ├─ 마이크 캡처: WebRTC getUserMedia → AudioWorklet (16kHz PCM)
  ├─ (선택) MediaPipe Face Landmarker — 온디바이스, 집계 지표만 송신
  ├─ 질문 오디오 재생: 사전 생성 캐시(주질문) + 스트리밍 수신(꼬리질문)
  └─ WebSocket ⇅ (오디오 업스트림 / 전사 파셜·TTS 오디오 다운스트림)

[세션 오케스트레이터 (서버, Node/Python — Pipecat·LiveKit Agents류 프레임워크 활용 가능)]
  ├─ 세션 상태 머신 실행 (트랙별 단계·타이머·하드/소프트 컷)
  ├─ VAD (Silero) — 발화 종료 감지(3초 무음+종결어), 무응답 10s/30s 트리거, 침묵 지표 수집
  ├─ STT 스트리밍 (RTZR WebSocket) — 파셜 전사 실시간 수신
  ├─ 턴 종료 시:
  │   ① 경량 LLM 1회 → 꼬리질문 트리거 T1~T7 판정
  │   ② questions.json 후속 매칭 or 면접관 LLM(스트리밍) 꼬리질문 생성
  │   ③ 꼬리질문 텍스트 → 스트리밍 TTS → 브라우저 재생
  └─ session_log 기록: 타임스탬프·질문ID·전사문·스피치 지표 (Redis: 활성 세션 / PostgreSQL: 영구)

[채점 파이프라인 (비동기 워커, SCORING 상태 진입 시)]
  ① 스피치 지표 확정: CPM(350~400 기준)·필러워드·침묵·답변 길이
  ② LLM 채점 × 위원 페르소나 2~3 (Batch API, 캐싱된 루브릭 프리픽스)
  ③ 과반수 집계 → 우수/보통/미흡 (평가루브릭-설계.md §4-3)
  ④ red flag 강제 반영
  ⑤ FEEDBACK 렌더: 등급 + 근거 인용 + 스피치 코칭 + 예상 꼬리질문 + 약점 보정 추천
```

### 6-2. 설계 결정 사항

1. **캐스케이드(STT→LLM→TTS) vs S2S(Realtime API)**: 채점을 위해 **정확한 한국어 전사문이 반드시 필요**하고(전사문이 채점·로그·모순 대조의 원천 데이터), 한국어 STT 정확도는 국내 특화 엔진이 우위이므로 **캐스케이드 채택**. S2S(gpt-realtime 등)는 지연은 낮지만 전사 품질 통제와 국산 STT 결합이 어렵다.
2. **지연 예산**: 발화 종료 감지 후 ~1초 내 면접관 첫 음성이 목표(음성 에이전트 통상 600~900ms). 파이프라인 전 구간 스트리밍 중첩(STT 파셜 → LLM 첫 토큰 → TTS 첫 청크)으로 달성. 단, 면접 도메인은 "면접관이 잠깐 생각하는" 1~2초 지연이 오히려 자연스러워 일반 콜봇보다 여유 있음.
3. **전송 계층**: 브라우저↔서버는 지연·방화벽 내성 면에서 WebRTC가 이상적이나, MVP는 WebSocket(48kHz→16kHz 다운샘플 PCM)으로 충분. LiveKit/Daily(Pipecat) 등 프레임워크 채택 시 WebRTC 무료 획득.
4. **세션 상태 관리**: 상태 머신·타이머·꼬리질문 뎁스 카운트·시간 예산(꼬리질문 40% 상한)은 오케스트레이터 메모리 + Redis 스냅샷(장애 복구용). 모든 상태 전환을 `session_log`에 append-only 기록 — T2(진술 모순) 대조와 채점 근거 인용의 원천.
5. **프롬프트 캐싱 적용점**: 면접관 LLM의 system(페르소나+트랙 규칙+작성 과제)은 세션 내 동결 → 턴마다 캐시 히트. 채점 LLM은 루브릭 전문을 프리픽스로 두고 위원 페르소나만 뒤에 배치하면 앙상블 3회 호출 중 2회가 캐시 읽기.
6. **비용 개략(1세션 30분 기준, 자릿수 감각)**: STT ~500원(RTZR 시간당 1,000원), 면접관 LLM+판정 LLM 수백 원(캐싱 적용 시), 채점 앙상블 수백 원(Batch), TTS는 꼬리질문 분량만 과금 → **세션당 총 1,000~2,000원대**로 추정. 상세 산정은 구현 후 실측 필요.

## 7. 구조화 면접 연구 (근거)

본 서비스가 재현하는 공무원 면접은 전형적 구조화 면접(고정 질문 풀 + 평정요소 + 앵커 척도)이며, 학술 근거가 탄탄하다.

- **Schmidt & Hunter (1998)**: 85년치 인사선발 연구 메타분석. 구조화 면접의 직무성과 예측 타당도 **r = .51** (비구조화 .38), GMA와 병용 시 .63 — 선발 도구 중 최상위. 이후 Sackett et al. (2022)이 보수적 보정으로 추정치를 하향했으나 **구조화 면접이 최상위 예측치라는 순위는 유지**.
- **Levashina, Hartwell, Morgeson & Campion (2014, Personnel Psychology 67:241-293)**: 구조화의 6요소 — 내용 측면(직무분석 기반 출제 / 전원 동일 질문 / 상황형·행동형 질문)과 평가 측면(답변별 평정 / 앵커 척도 등). 행동형(과거경험)·상황형 질문 모두 높은 신뢰도·타당도 확인. → 본 시스템의 "경험형 STAR 검증 + 상황형 조건 변경 압박" 설계와 직접 부합.
- **AI 채점–인간 채점 일치도**:
  - 자동 화상면접(AVI) 역량 채점 연구에서 ICC 중앙값 **.96**(범위 .74~.99) 보고 사례(단, 벤더 자체 데이터 기반이라 일반화 주의).
  - 훈련된 인간 평가자 간 신뢰도가 통상 r=.6~.8 구간이므로, AI가 인간과 r≈.7이면 "인간 평가자 동급"으로 해석하는 것이 학계 관례. 벤더의 "85% 일치" 류 수치는 자체 루브릭·자체 데이터 기준임에 유의.
  - 국내: 마이다스 AI역량검사 — KAIST 연구팀이 간호직 282명 대상 1년 후 직무성과 예측력을 인간 면접과 비교한 연구가 Scientific Reports 게재(AI 검사만 전 영역 유의한 예측력). 한국경영학회 공동 분석(16개 기업 재직자 4,041명)에서 성과 상관 r=.52 보고. 단, 이는 벤더 주도 연구로 독립 재현은 제한적.
- **시사점**: (a) 채점은 반드시 루브릭 앵커 기반으로(자유 인상 평가 금지), (b) AI 채점의 신뢰도 검증은 인간 평가자 2인 이상과의 ICC/상관으로 자체 측정해 공개, (c) 표정·비언어 신호는 타당도 근거가 약하고 규제 리스크가 있으므로 등급 미반영(코칭 전용) — 세션 설계 문서 원칙 유지.
